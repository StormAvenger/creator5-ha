# 0.6.0 — File tools and optional sidebar

Experimental; use at your own risk. Only Creator 5 Pro has prior physical use.
Standard Creator 5 and these new file actions remain hardware-unverified.

- Hide the tools sidebar shortcut by default, including on upgrades. Keep access
  from the integration's Configure form; add an opt-in visibility setting.
- Add on-demand recent-file listing and bounded PNG/JPEG previews.
- Add a separate default-off file-action preference and admin-only, single-use,
  60-second confirmations for upload-only, reprinting and cancellation.
- Upload trusted sliced `.3mf`/`.gcode` up to 64 MiB under unique filenames. Validate
  archive structure/limits, use private temporary storage, require ready status,
  send no material mappings and never start automatically.
- Reprint only after fresh ready/list checks and explicit bed/material confirmation.
  Always request leveling. Use slicer-numbered default slots; previous custom
  mappings and HA monitoring notes are not applied or guessed.
- Cancel only a freshly identified active/paused job, with filename/elapsed checks.
  Never clear its dialog automatically or retry a write after a timeout.
- Let users choose sidebar visibility when creating a new native dashboard;
  existing dashboards, cards, automations, entities and preferences are preserved.
- Document future protocol research separately. No hidden-service, firmware,
  motion, fan, extrusion, calibration or generic-command feature is added.

See [file tools and limitations](../files.md). In particular, the printer exposes
no atomic job ID for cancellation and no stored-file material requirements. Slow
transitions can yield an unconfirmed result; inspect the printer before retrying.
The firmware 2.0.0 light issue is not claimed fixed.

## Validation

252 standalone client tests, 106 real HA 2026.10.1 tests and 24 frontend workflow
checks pass (382 checks). Coverage includes changed jobs/state, confirmations and
revocation, admin/auth boundaries, multipart transport to a loopback mock printer,
upload-only headers, temporary-file cleanup, filename/response/archive bounds,
sidebar toggles/collisions, and existing monitoring/controls/usability regressions.
The tools UI was visually checked with synthetic data in Chrome.

Lint, formatting, strict client typing, official hassfest, clean package and
privacy checks are run locally. No live HA update/restart, printer read/write or
real notification was performed. No hosted workflows or paid GitHub features are
used; Actions remains disabled. Physical firmware acceptance is a separate step.
