# 0.7.0 — Alert pictures and reliability fixes

Experimental; use at your own risk. Only Creator 5 Pro has prior physical use.

## Alert pictures (new, off by default)

- Optional camera picture on completed, bed-cooled, error and prolonged-pause alerts.
  If the chamber light is off it is switched on, the integration waits (default
  10 s), grabs one frame, sends the alert, then switches the light off again.
- The only printer commands are the existing chamber-light on/off, each sent once,
  only when the light reported off. Unconfirmed commands (firmware 2.0.0) still get
  a picture; the light is restored only if a fresh read shows it on.
- Pictures are saved to Media → creator5 (20 per printer) and attached to new phone
  alerts. Existing alert automations are unchanged; see [usability](../usability.md).

## Reliability fixes

- **Connection-lost alerts** fire only when the outage starts during a job
  (printing, heating, paused or calibrating). Powering off an idle, completed,
  errored or auto-shut-down printer no longer alerts.
- **Printer off when HA starts:** once a printer has been set up successfully, its
  model is saved. If it is off at startup, the integration loads with unavailable
  readings instead of retrying setup, so Last print, maintenance records and
  connection status stay visible. Polling continues and readings return when the
  printer is switched on. The device keeps its last reported model/firmware.
  Existing entries save the model on their first successful start after updating.
- **IP address changes:** new **Reconfigure** step for address and LAN code. It
  identifies the printer at the new address and refuses a different serial number,
  so history and settings are kept. Adding an already configured printer from a new
  address now updates the saved address instead of only aborting. A custom camera
  URL pointing at the old address is ignored rather than blocking setup.
- **Printer error** binary sensor is on whenever the printer reports an `error`
  state, including when its error code is empty.
- **Failed prints:** Last print gains a `failed` outcome for jobs that saw an error
  and then ended without completing. Recovered errors still complete, with the code
  kept in `error_code`. Plain returns to ready without an error stay `unconfirmed`.

## Validation

252 client tests, 136 real HA 2026.10.1 tests (30 new) and 24 frontend checks pass.
The reliability tests fail against 0.6.0 except four that guard existing behavior.
Picture tests cover light order, already-on and unknown lights, unconfirmed commands,
failed captures, retention and the generated phone/panel alert data. Ruff,
formatting and strict client typing pass. Tests use synthetic data only; no live
HA install, printer read/write, real notification or hassfest run was performed.
